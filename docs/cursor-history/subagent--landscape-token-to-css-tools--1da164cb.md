## Digest: tokens JSON → CSS (2025–2026)

**Jugadores.** **Style Dictionary** (v4/v5) es el estándar: CLI + API Node, transforms/formats extensibles, CSS/SCSS/JS + iOS/Android. DTCG de primera clase; v5 avanza hacia **DTCG 2025.10** (color/dimensiones estructurados). **Tokens Studio** es authoring/Figma + sync Git; desde 2026 **DTCG por defecto**; no genera CSS solo: exporta JSON y enlaza con SD vía **`@tokens-studio/sd-transforms`**. **Theo** (Salesforce) está en legado; el propio Salesforce migró a SD. **Terrazzo** (ex Cobalt): DTCG-nativo, CLI plugin (`@terrazzo/plugin-css`), CSS-first, lint. Emergentes CSS/DTCG: **Dispersa**, **design-token-kit**, wrappers tipo **dtcg-tools**. “cssgen” no es un jugador de referencia frente a este stack.

**Posicionamiento típico.** CLI + config (pipelines CI) + API programática. Formatos: JSON/JSON5/YAML → CSS custom properties, SCSS vars/maps, JS/TS; SD también nativo. Mixins Sass: **no nativos**; SD emite variables/maps (`scss/variables`, `scss/map-*`); mixins = formato custom. Salida CSS = `:root` / selectores + shorthands tipografía/borde/sombra.

**Dónde diferenciarse.** El mercado está saturado de **orquestadores multipplataforma** (SD) y **herramientas de diseño** (Tokens Studio). Queda espacio para una **lib API-first** (CLI opcional) solo **JSON tokens → archivos CSS**: detección de taxonomías (3-tier / CTI / OO), resolución de aliases DTCG, CSS predecible sin config de 10 plataformas. Complementar SD, no competir en iOS/Android; opcionalmente validación DTCG 2025.10 y modos/temas ligeros.
