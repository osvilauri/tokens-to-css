The Six-Stage Contract

What the library is allowed to do, in what order, and what it must refuse — fixed before a line of it exists.

29 Aug 2026 22 invariants status final altitude feature

What this governs

The library takes one design-token JSON file — from a path or a URL — and writes one CSS file of custom properties. It does not transform values, does not target iOS or Android, and ships no command-line tool. That narrowness is the product.

An architecture spine is not a design document. It fixes only the calls that two people, building two halves of this independently, could answer differently and still both be right. Everything a future reader could work out by looking at compliant code was left out on purpose.

The test applied to every candidate decision: could two units one level down choose incompatibly? If not, it isn't here.

The shape

touches disk or network pure function — no IO, no clock, no randomness the only way to fail

Pipes and filters, with the IO pushed to both ends. The four middle stages are ordinary functions you can call in a test without a filesystem. Nothing between them may import node:fs or open a socket — which is what makes the fixture corpus cheap enough to be the primary test suite.

The decisions that carry weight

Twenty-two invariants are recorded. These six are the ones the rest hang from.

AD-1

The pipeline is the only control flow

One file sequences the six stages. A stage takes the previous stage's output and returns the next stage's input — never a callback into a later one.

PreventsA shortcut path that reaches the writer without passing validation.

AD-4

One error type; the codes are the contract

Every failure throws the same class, carrying a code from a frozen list. No error subclasses, no returned null, no stage signalling failure in its own dialect.

PreventsCallers matching on message text — which would make every wording change a breaking change.

AD-5

Fail closed, one class at a time, exhaustively

Validation passes run in a fixed order. Each pass walks the whole document and reports every offender of its class; the first failing pass stops the run.

PreventsWhack-a-mole: fix one token, rerun, discover the next. You get the whole class at once.

AD-6

Nothing is written until the whole output exists in memory

The emitter returns a complete string. The writer is the first code to open the output path, and it runs only after every check has passed.

PreventsA streaming emitter leaving half a stylesheet on disk when validation fails late.

AD-8

All network policy lives in one guarded adapter

Built on node:https with a custom DNS lookup, so the socket connects to the address that was actually checked. Redirects are followed by hand and re-validated at every hop.

PreventsA redirect walking out of the guard and into a cloud metadata endpoint.

AD-13

Zero runtime dependencies

The published package installs nothing. Node builtins only. Adding a runtime dependency needs an explicit amendment to this document.

PreventsSlowly becoming the heavy toolchain the product exists to avoid.

What the review pass caught

The spine was drafted, then attacked: construct two implementations that obey every rule and still produce different output. Five of those exist — and four of them changed the emitted CSS, which is the part under a version guarantee. Each became a new invariant.

What does the number 16 become?

The internal model carried string | number, and nothing said how a number reaches the stylesheet. One builder writes 16. Another, reasoning that spacing must be a length, writes 16px. Both followed every rule.

AD-19 — one stringify function; strings verbatim, numbers via String(n), no unit inference ever. Booleans, null, objects and arrays are refused.

Is "1px solid {color.border}" a reference?

A value that is entirely {color.border} is obviously an alias. A value that merely contains one was undecided. Treat it as a literal and you ship dead CSS that a browser accepts silently — the exact failure mode the whole product forbids.

AD-20 — a reference only when the whole string is one. Anything embedded is refused by name.

Which Tokens Studio keys disappear from the name?

Wrapper keys don't become part of a custom property's name. But which keys are wrappers was never stated — so one builder emits --global-color-brand-primary and another --color-brand-primary. Two compliant implementations, two incompatible public contracts.

AD-22 — only top-level keys are set wrappers; more than one set is refused outright.

Who owns each rejection?

The order of validation passes was fixed. Their membership was not. "Mixed-dialect token node" could plausibly live in detection or in validation — so it gets reported twice, or, worse, each side assumes the other has it.

AD-21 — an exhaustive table assigning every rejection trigger to exactly one module.

A rule that could not be implemented

The first draft routed remote fetching through the global fetch while demanding per-hop IP validation. fetch never exposes the address it resolved, and pinning a connection to a checked one requires a library that isn't a Node builtin — which would have broken the zero-dependency rule two pages earlier.

AD-8 rewritten — node:https with a custom lookup and node:net.BlockList. Both builtins.

The public surface

Two things are frozen under semantic versioning, and both are outputs rather than function signatures: the names this library emits, and the codes it fails with. Changing either is a major release.

Failure codeRaised when
SOURCE_UNREADABLEThe path or URL cannot be read, times out, is too large, or violates the network policy
SOURCE_INVALID_JSONThe content is not valid JSON
FORMAT_NOT_ALLOWEDThe shape is not on the allowlist — including embedded references and mixed dialects
ALIAS_CYCLEAliases reference each other in a loop
ALIAS_DANGLINGAn alias points at a token that does not exist
COMPOSITE_VALUEA value is an object, array, boolean, or null rather than a scalar
NAME_COLLISIONTwo tokens would produce the same custom-property name
OUTPUT_WRITE_FAILEDThe stylesheet could not be written

Every one of these has a fixture that must fail with exactly that code. Every accepted shape has a fixture whose output is compared byte for byte against a stored file. Those stored files only change under an explicit flag, and changing one requires shipping a major-version note in the same pull request — which is what stops "just regenerate it" from quietly rewriting the contract.
