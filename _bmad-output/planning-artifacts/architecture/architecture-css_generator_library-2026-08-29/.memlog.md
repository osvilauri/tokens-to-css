- (decision) AD-1 Paradigma: pipes-and-filters con nucleo funcional / cascara imperativa. Etapas load -> detect -> normalize -> validate -> emit -> write; detect/normalize/validate/emit son puras. Previene: IO (fs/red) disperso dentro del parseo y la emision, etapas no testeables sin disco.
- (decision) AD-2 Una sola representacion interna (IR) en las fronteras de etapa: lista ordenada de tokens {path: string[], value: Scalar | Ref}. Solo los normalizadores leen claves de dialecto. Previene: que el validador o el emisor vuelvan a olfatear $value vs value; fuga de logica de dialecto aguas abajo.
- (decision) AD-3 La Format Allowlist vive como registro cerrado y ordenado de dialectos (datos, no if-chains) con precedencia fija A3 -> A1 -> A2 -> reject. Anadir una forma = una entrada del registro + fixtures accept/reject. Previene: deteccion no determinista y crecimiento del allowlist por parche disperso (SM-C3).
- (decision) AD-4 Un unico tipo de error exportado (TokenCssError) con propiedad code tomada de un objeto congelado de codigos. Nada de subclases por fallo, nada de retornar null. Previene: que el llamador haga string-matching y que convivan estilos de error distintos.
- (decision) AD-5 Pipeline fail-closed: ninguna etapa devuelve resultado parcial. Los pases de validacion corren en orden fijo (estructura -> dialecto -> composites -> grafo de alias -> naming/colisiones); cada pase recorre TODO y reporta todos los infractores de su clase; el primer pase que falla aborta. Previene: correccion whack-a-mole y mezclas de agregacion incoherentes.
- (decision) AD-6 Nada toca el sistema de archivos de salida hasta que la validacion completa pasa: el CSS se construye entero en memoria y solo entonces se escribe. Previene: escritor en streaming que deja archivo parcial (FR-2, FR-19).
- (decision) AD-7 Escritura atomica: archivo temporal en el MISMO directorio destino, luego rename. En cualquier fallo se borra el temporal y el archivo previo queda intacto. Previene: Styles File truncado o temporales huerfanos.
- (decision) AD-8 La descarga remota vive en un unico adaptador guardado que implementa los minimos de PRD §9: https por defecto, redirects en modo manual con re-validacion de cada salto (esquema, host, rango IP), timeout y tamano maximo. El nucleo nunca recibe una URL, solo bytes ya validados. Previene: que cada llamada reinvente su politica de red y que un redirect evada el guardia (SSRF).
- (decision) AD-9 Normalizacion a prueba de prototype pollution: los objetos del arbol se construyen con Object.create(null) y las claves __proto__/constructor/prototype a nivel de token son rechazo duro (clase FR-14), nunca omision silenciosa.
- (decision) AD-10 Determinismo por construccion: el orden de documento se transporta en arrays, nunca en iteracion de claves de objeto ni en orden de Set/Map. El CSS emitido no contiene timestamps, versiones ni rutas. Previene: golden files que cambian solos y rompen SM-1.
- (decision) AD-11 Regla de naming, casos borde (delegados a arquitectura por FR-9): normalizacion Unicode NFC, minusculas locale-independiente, todo lo que no sea [a-z0-9] colapsa a un solo guion, se recortan guiones de los extremos. Un segmento que normaliza a cadena vacia es fallo duro, no se omite. Los digitos iniciales se permiten (validos en custom properties).
- (decision) AD-12 La deteccion de colisiones (FR-21) opera sobre los nombres finales ya normalizados, no sobre las rutas, y agrupa todos los conflictos antes de fallar.
- (decision) AD-13 Cero dependencias de runtime: solo builtins de node: y fetch global. Las devDependencies son libres. Previene: arrastrar un parser JSON alternativo o una libreria de color y contradecir PRD §10.
- (decision) AD-14 Superficie publica de un solo modulo: src/index.ts exporta Main Entry, la clase de error, los codigos y los tipos. Sin subpaths en exports, sin deep imports. Previene: que lo interno se vuelva API por accidente y bloquee refactors bajo semver.
- (decision) AD-15 Main Entry: generateCss(source: string | URL, options?: GenerateCssOptions): Promise<GenerateCssResult>. El result NO lleva CSS (PRD §5) sino {outputPath, tokenCount}. Options: outDir, fileName, baseDir, http{allowInsecure,timeoutMs,maxBytes,maxRedirects}.
- (decision) AD-16 Corpus de fixtures dirigido por el sistema de archivos (OQ-1): fixtures/accept/<dialecto>/<jerarquia>/{input.json,expected.css} y fixtures/reject/<trigger>/{input.json,expected.json con code y tokenPaths}. El runner descubre carpetas; anadir una carpeta anade un caso. Previene: manifiestos que se desincronizan del disco.
- (decision) AD-17 Protocolo de golden files: se regeneran solo con UPDATE_GOLDEN=1; el diff de un golden debe aparecer en el PR; cambiar un golden existente exige changeset major salvo que el fixture sea nuevo. Cierra la mitad de protocolo de OQ-1.
- (decision) AD-18 Envolvente operativa (es una libreria, no hay despliegue): CI en GitHub Actions con matriz Node 22/24/26, publicacion npm con provenance via Changesets. Sin entornos ni infraestructura de runtime.

- (decision) AD-8 CORREGIDO tras el gate: el adaptador remoto se construye sobre node:https con lookup personalizado (conecta a la IP ya validada) y node:net.BlockList, no sobre fetch global. - (decision) AD-19 (nuevo, del gate): stringifyLiteral unico y puro. String verbatim sin comillas; number como String(n) sin inferencia de unidades; cualquier otro valor JSON (boolean, null, objeto, array) falla con COMPOSITE_VALUE. Previene que un builder emita 16 y otro 16px.
- (decision) AD-20 (nuevo, del gate): un valor es referencia solo si la cadena ENTERA calza ^\{[^{}]+\}$. Una cadena con {…} embebido es FORMAT_NOT_ALLOWED. Previene emitir '1px solid {color.border}' como CSS muerto.
